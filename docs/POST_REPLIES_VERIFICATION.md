# v3.3.4 帖子回复展开验证（构建 340）

日期：2026-11-05。本轮版本 `3.3.4+340`，基于构建 `339` 补齐帖子回复，覆盖更新同名 `v3.3.4`。

## 上一版为什么禁用

上一版完成了混合章节讨论列表，却尚未验证帖子的子回复协议。帖子下的第一层“回复”实际上是帖子评论，要调用 `comment/list/{postId}`；楼中楼才调用 `reply/list/{commentId}`，并携带所属帖子 ID。把帖子 ID 直接发给原章评回复读取方法会产生错误/空结果，因此上一版用明确的“暂不支持”提示代替错误展开。这是客户端未接入，不是官方禁止读取。

## 本轮实现

- 帖子回复：`POST /novel/commentapi/comment/list/{postId}/v1/`，`comment_source=5`、`comment_type=11`、`group_type=3`、`server_channel=35`，带所属书 ID、计数及原始 JSON 游标。
- 楼中楼：`POST /novel/commentapi/reply/list/{commentId}/v1/`，读取上下文仍为 `source=5 / type=11 / group=3`，携带 `group_id=postId` 和书 ID；不能将其他场景的 `NovelPostReply=505` 直接替换到这个读取请求。
- 第一层评论转换为回复模型并保留其子回复数量。楼中楼保留回复对象、作者标记、正文、图片、时间和点赞数量；旧回复缓存 JSON 可继续读取。
- 章评、帖子和楼中楼分别按类型及所属帖子标识存储展开状态。同 ID 不共享线程；立即展示加载状态，收起、重新展开、刷新和销毁时忽略旧请求的迟到结果。
- 分页保留服务端游标并按回复 ID 去重，复制到面板自己的可变列表。失败或游标未推进保留已有回复及原游标并显示重试；不把接口失败/格式不支持当成“没有回复”。
- 有回复的帖子显示展开入口，真实无可见回复显示空态；普通章评仍走原接口。窄屏与双倍字号下，回复用户名、作者标记、时间和大点赞数可换行布局。

真实接口复验：

```sh
flutter test --no-pub test/post_replies_live_test.dart \
  test/chapter_discussion_live_test.dart \
  --dart-define=FANQIE_LIVE_API=true --reporter expanded
```

用例只记录数量，不记录书友的真实资料或回复正文。单元用例使用匿名构造数据；真实测试依赖官方接口与当时数据，后续数量或网络可能变化。

## 范围

仅实现读取和展开，不增加登录、发帖、发布回复或点赞操作。帖子楼中楼与“作者有话说”话题下的讨论列表是两种资源，后者仍未接入。回复不新增磁盘离线缓存；读取失败时保留当前已经展开的内容并提示重试。本轮没有 Android 设备测试，不将历史设备结果当成本轮结果。
