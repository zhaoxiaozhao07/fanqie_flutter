## 三、固定技术方案与接口变化

### 3.1 架构与平台边界

- 保持同一 Flutter 项目、Dart 服务引擎、数据模型和阅读器，不另建 Windows 项目或 Python 后端。
- 上游请求中的 Android 协议参数属于现有接口协议，不因客户端运行在 Windows 就改成 `windows`。
- 扩展 `ReaderSystemService` 为平台能力统一入口，增加可注入的 `ReaderPlatformCapabilities`；界面按实际能力显示功能。
- 保留现有平台通道名称 `com.fanqie.fanqie_flutter/download`，避免同时重命名 Android 通道、事件总线和测试。
- Windows 原生适配集中在 runner 内的独立 C++ 模块，不把业务代码散落进窗口入口。
- 原生后台转码完成后回到 Flutter 平台线程返回结果；取消、销毁和迟到结果必须隔离。
- Windows 首版听书能力为关闭状态，隐藏播放入口、面板和设置，避免初始化时仍调用不存在的原生方法。

**数据兼容：**不重定义 `ReadingPosition`、阅读快照、书签、笔记和备份格式，不为桌面适配迁库。

### 3.2 依赖处理

| 依赖 | 处理 |
|---|---|
| `path_provider`、`shared_preferences` | 已有 Windows 实现，保留并验证实际落盘路径 |
| `file_picker 13.3.1` | 保留打开文件与选择目录能力 |
| `flutter_cache_manager` | Windows 默认使用 JSON 缓存仓库，不因间接依赖 sqflite 就另加数据库 |
| `permission_handler` | 保留 Android 用途；Windows 文件流程不调用 Android 存储权限 |
| HTTP、加密、HTML/XML、归档、SVG 等 | 保留，禁止无关主版本升级 |
| 新增 `window_manager: ^0.5.1` | 窗口事件、关闭拦截、全屏、尺寸管理 |
| 新增 `file_selector: ^1.1.0` | Windows 仅获取保存位置，再流式复制生成文件 |

新增依赖后提交锁文件并执行双平台回归。`file_picker` 当前保存接口要求完整字节数组，因此不用于可能接近 1 GB 的备份保存，避免额外整包内存复制。

### 3.3 文件与持久化

- 新增统一 `AppStoragePaths`：Android 保留原目录；Windows 使用应用支持目录。
- Windows 固定资源身份：`CompanyName=com.fanqie`、`ProductName=FanqieReader`，使升级和移动 ZIP 解压目录不改变数据位置。
- Windows 持久数据预计位于 `%APPDATA%\com.fanqie\FanqieReader`；通过插件获取，不硬编码用户名。
- 原生 EXE、数据目录与导出目录分离。存储初始化失败时明确提示，不把阅读数据静默保存到系统临时目录。
- 文件系统路径使用 `path`；ZIP/EPUB 内部资源名继续使用 POSIX 路径。
- 修正依赖 `/` 的插图识别、容量统计与清理规则，验证 Windows 目录枚举返回值。
- Windows 落盘路径拒绝目录穿越、ADS、设备保留名、尾点/尾空格及大小写冲突；不能降低现有 ZIP 校验。
- 同目录暂存后提交。Windows 已存在文件采用 `ReplaceFileW`，新文件采用 `MoveFileExW`；失败保留旧文件，禁止先删旧文件再写新文件。
- 原子写入、缓存写入及恢复目录交换统一接受 Windows 文件占用、权限和磁盘不足测试。

**导出接口变化：**

- 导出保存返回可空的实际路径：`null` 表示用户取消，不能显示“已导出”。
- 下载任务增加 Windows 输出目录，启动前确定；默认用户 Downloads 下的 `fanqie` 子目录，可选择其他目录。
- 下载结束不突然弹保存对话框；重名自动追加序号，不静默覆盖其他文件。
- 笔记与备份使用“另存为”，流式写入选择位置，成功后才提示实际路径。
- 下载历史仅记录真正提交成功的文件路径。

### 3.4 桌面界面与生命周期

- 使用 Windows 原生标题栏，不重做自绘窗口边框。
- 初始窗口 `1100×760` 逻辑像素，最小目标 `720×520`；均受当前显示器工作区约束。
- 保存普通窗口尺寸、位置和最大化状态；重开时校正到可见显示器，不恢复越界窗口。
- 主界面宽度达到 `900` 时使用侧导航，较窄时保留底部导航。断点变化不能销毁现有页面、滚动位置和请求状态。
- 主界面内容最大宽度 `1200`；阅读区域最大宽度 `840`，居中单列，不新增双页阅读。
- 阅读头部、状态栏、正文与点击热区使用同一阅读区域。分页、段落高度、图片布局和锚点恢复必须使用真实内容尺寸，而非整个窗口宽度。
- 设置弹窗最大宽度 `640`，目录/评论/搜索等面板最大宽度 `760`，高度不超过可用区域的 85%，内容可滚动。
- 宫格按约 `200` 逻辑像素目标卡宽计算列数，复用现有大字布局规则。
- 保留单段精确选区模型，补齐鼠标拖选、双击选词、右键菜单和复制；首版不新增跨段批注。
- 鼠标拖选不得触发翻页；触摸翻页保留。分页滚轮按连续事件节流，滚动模式使用正常滚动。
- 窗口失焦或最小化暂停自动滚屏与看书计时；重新获得焦点不擅自推进正文。
- 原生单实例保护，防止两个进程并发写同一数据目录；再次启动激活已有窗口。
- 关闭窗口前主动捕获当前阅读锚点，再等待进度、偏好、笔记和统计落盘，不能仅依赖 `dispose()`。
- 活动下载提供“返回应用”或“取消任务并退出”；导入提交、恢复等关键事务完成前不允许正常关闭。
- 不持久化下载队列；重新启动保留已完整缓存的章节，但不承诺自动恢复任务。

| 快捷键 | 行为 |
|---|---|
| ←/→、PageUp/PageDown | 上一屏/下一屏，沿用现有边界切章规则 |
| Ctrl+←/→ | 上一章/下一章 |
| Ctrl+F | 阅读正文搜索 |
| Ctrl+B | 当前位置书签 |
| Ctrl+, | 阅读设置 |
| Ctrl+O | 主界面打开本地导入 |
| F11 | 切换全屏 |
| Esc | 依次处理顶层弹窗、选区、全屏、阅读菜单、页面返回；不直接退出应用 |
| Ctrl+C | 使用正常文本复制，不被阅读快捷键覆盖 |

文本输入、选区和弹窗获得焦点时，阅读快捷键不得误触发。

### W3：中文编码必须保持的行为

- UTF-8、UTF-16LE/BE 保留严格校验与 BOM 处理。
- 自动模式与 Android 保持同一选择顺序：BOM → 严格 UTF-8 → GB18030。
- GBK 作为 GB18030 的兼容子集处理；Big5 通过手动选择。
- Windows 转码在后台执行，保留跨块多字节字符和取消能力，不依赖系统当前代码页。
- 沿用 128 MB 输入文件上限和现有 EPUB 图片/解压限制。

### W7：听书后续路线

- 复用现有 `TtsService`、`TtsInvoker`、切片与原文映射，不重做播放队列。
- 系统语音使用 Windows SpeechSynthesizer；缺少可用中文音色时明确提示，不静默使用错误语言。
- 合成语音与网络音频使用统一 MediaPlayer，保留播放 token、迟到事件隔离、错误暂停和实际引擎状态。
- 密钥采用用户级 DPAPI，不保存明文、不进入备份或日志。
- 音量淡出只调整本应用播放器，禁止修改系统总音量。
- 系统媒体播控接入暂停/继续、上一段/下一段与停止；最小化可继续，退出进程即停止。
- 睡眠定时采用绝对截止时间；验证锁屏、系统睡眠恢复、输出设备断开和快速切书。
- 不将 Android 前台服务、音频焦点测试直接当作 Windows 验收。
- Android/Windows 数据迁移仍为独立后续任务，不随听书阶段自动纳入。

### 5.3 发布约定

- 完整打包 `build/windows/x64/runner/Release` 内容，不能只发布 EXE。
- 包含所需 Flutter/插件 DLL、`data` 资源、获准再分发的 MSVC 运行库和第三方许可证。
- ZIP 命名：`fanqie-v<版本>+<构建号>-windows-x64.zip`，附 SHA-256。
- 使用 PowerShell 打包与验证脚本，每条原生命令检查 `$LASTEXITCODE`，失败立即退出。
- Windows 发布流程独立于现有 Android 快速发布流程，先采用手动触发。
- 版本继续取自 `pubspec.yaml`；本次文档任务不提前修改版本号。
- GitHub Release 仅增加 Windows 产物，不覆盖或删除 APK、Android 校验文件及签名配置。
- 首版可不配置代码签名，但必须说明可能存在 SmartScreen 提示，不能要求用户关闭系统防护。
- 发布说明明确首版不含听书、托盘、跨端迁移、安装包和自动更新。
