# 沉浸式多角色听书开发计划

- 文件：plan.md
- 配套配置：config.example.json
- 版本：1.0
- 更新日期：2026-11-25
- 使用对象：负责在现有 EPUB / TXT 阅读器中实现功能的 AI 开发者
- 文档性质：可执行的开发规范与验收计划；当前交付的是设计和配置示例，不表示现有项目已完成这些功能。

## 0. 执行说明

先完整阅读本文件和同目录的 config.example.json，再检查现有项目，按第 17 节的阶段实施。不得仅制作设置界面、模拟进度或静态演示后宣称功能完成。

现有条件：阅读器已经支持 EPUB、TXT，并已接入 OpenAI 兼容 TTS。应复用其书库、正文解析、目录、定位、播放器、配置存储和已有接口代码。实际语言、框架、桌面或移动平台未知，先检查项目再选择具体实现库，禁止凭空重建阅读器或强制迁移技术栈。

默认架构采用“持久化状态 + 有界异步任务队列 + 供应商适配器”。单机实现优先使用现有事务数据库；没有适合的持久化数据库时，使用 SQLite。示例配置使用 SQLite。已有服务端或事务存储时可以复用，但必须提供等价的事务、唯一约束、任务认领与版本保护，且同步调整配置 Schema 和示例。不得因本功能默认引入 Redis、消息中间件或多智能体框架。

用户的明确要求：

1. 同一个供应商能够配置多个模型，每个模型能够配置多个音色。
2. 模型与音色标识精确保留大小写。例如同供应商的 X/Y、x/y、x/Y 是三个独立组合。
3. 每个音色配置有独立名称、备注、性别标签，并能由每本书勾选。
4. 一个 OpenAI 兼容文本模型负责分析书籍，可以配置并发数。
5. 全部勾选音色的信息进入系统消息；固定旁白专门处理非人物直接发言。
6. 使用接口原生结构化 JSON 返回，禁止以“请输出 JSON”的提示词方案代替接口能力。
7. 跨分段、跨章节保持角色身份和已确认音色一致。
8. 提前分析后续章节，异步生成并缓存音频，严格按照原文顺序朗读。
9. 必须交付可编辑的 config.example.json，包含供应商、模型、音色和其余运行配置。
10. 不要求先分析整本书才能开始播放。

本次功能不扩展背景音乐、音效制作、声音克隆、自由聊天、配音商城、分享平台、角色图片等内容。内心活动和引用文字首版统一由旁白朗读。

### 0.1 AI 实施时应产生的交付物

| 交付物 | 要求 |
|---|---|
| 现有项目的功能代码 | 正文分析、角色记忆、任务调度、TTS 缓存、顺序播放、配置与必要 UI |
| config.example.json | 与真实加载器和默认值一致；不含真实密钥；不能只有两三个演示字段 |
| config.schema.json | 实施时生成，严格校验完整配置并给出字段路径错误；示例必须通过 |
| 原生输出 Schema | 分段分析、身份复核、摘要更新等任务有独立版本化 Schema |
| 数据库迁移与恢复逻辑 | 不损坏既有书库、阅读进度和原有 TTS 配置 |
| 自动化测试及最小测试书籍 | 覆盖第 16 节的关键行为，不能只检查函数存在或页面能打开 |
| 项目内接入说明 | 填写配置、测试连接、开始听书、查看问题、恢复任务 |
| 实施记录 | 实际采用的文件、命令、验证结果、未完成项；没有密钥时如实区分模拟测试与真实联调 |

不得覆盖用户已有 config.json。首次运行可提供“从示例创建配置”的操作；配置含占位值时关闭本功能并明确指出需要填写的字段。功能关闭时原有阅读与普通听书仍应正常运行。

## 1. 已选定的处理方案

采用：**原文固定定位 → 滚动分块预分析 → 按原文顺序确认角色 → 固定音色绑定 → 按需并发合成与缓存 → 连续顺序播放。**

并发模型只产生候选结果，不能直接创建正式角色、修改固定音色或调用 TTS。应用是角色身份、绑定、播放顺序和原文覆盖的权威来源。

### 1.1 默认运行参数

以下数值是可调整的启动配置，不是供应商性能或准确率承诺。实际压测后可调整，但必须同时更新示例和文档。

| 项目 | 默认值及定义 |
|---|---|
| 章节预分析 | 当前章节 + 后 3 章；ahead_chapters 不含当前章 |
| 分块预分析边界 | 最多向当前分析前沿外派发 24 块；未有序提交的结果最多 8 块 |
| 文本模型并发 | 4；其中 1 个位置保留给身份复核 |
| TTS 总并发 | 6 |
| 示例供应商并发 | A 为 4，B 为 2；同供应商的所有模型共享其上限 |
| 首播缓冲 | 从当前光标连续可播 8 秒；首段就绪后等待 3 秒仍未达标，可先播已有连续内容 |
| 补缓冲阈值 | 连续可播时间低于 90 秒时提高近期合成优先级 |
| 目标缓冲 | 300 秒 |
| 最大预取水位 | 600 秒；已就绪 + 在途估计值用于限制新任务 |
| TTS 待处理任务 | 最多 64 个，包括排队、重试等待及在途任务 |
| 越过首个音频缺口的投机任务 | 最多 8 个；不能越过身份未确认边界 |
| 音频缓存 | 2 GiB；触发清理后尽量降至 80%，保留至少 256 MiB 磁盘空闲 |
| 暂停 | 停止新预取；在途请求可完成并缓存 |
| 从中间章节首次起听 | 若缺少前缀身份状态，先补齐前文角色分析，不生成前文音频 |

缓冲秒数按当前播放倍速折算。分析并发、供应商请求并发、缓存容量和实际可播缓冲是四个不同维度，不能互相替代。

### 1.2 必须始终成立的不变量

1. 同一个已确认 character_id 只能有一个当前生效的正常角色音色绑定，除非用户明确修改或执行身份冲突修正。
2. 允许多个角色共用音色，不允许因为共用音色而合并人物身份。
3. provider_id、model_key、voice_profile_id 是应用内部标识；远端 model_id、voice_id 按原值发送。
4. 不把 X 与 x、Y 与 y 转成同一个值；不按显示名或数组下标做身份识别。
5. 模型只引用原文片段，实际合成文本由程序从不可变原文取回。
6. 当前目标范围必须恰好覆盖一次；只读前后文不得进入本次配音清单。
7. 未经有序接受分配决策的草稿不得生成正式音频；正常人物需要确认角色，已审核的未知对白可按明确兜底策略接受。
8. 原生 JSON 合法不等于角色判断正确；结构、原文、身份、配音分别校验。
9. 一个供应商故障不能静默更换角色音色。
10. 音频完成顺序不影响播放顺序；前面缺段时等待，不跳过。
11. 跳章不清空全书角色记忆，暂停不删除已生成音频。
12. 重试、应用重启和旧请求晚返回不能重复创建角色或覆盖新版本。
13. 一个角色的音色改变，只影响依赖它的清单和音频引用。
14. 固定旁白、角色候选池、每本书的锁定绑定均持久保存。
15. 模型输出不得直接修改配置文件、密钥、任务优先级或执行工具。
16. 已确认的原文证据、身份归并记录不随调试日志过期删除。

## 2. 模块与职责边界

~~~mermaid
flowchart TD
    A["阅读器正文与稳定位置"] --> B["分块和上下文组装"]
    B --> C["并发候选分析"]
    C --> D["有序身份确认"]
    D --> E["已确认配音清单"]
    E --> F["异步 TTS 与音频缓存"]
    F --> G["顺序播放器"]
    H["角色档案与固定音色"] --> B
    D --> H
    D -->|"有歧义"| I["局部身份复核"]
    I --> D
~~~

| 模块 | 负责 | 不得承担 |
|---|---|---|
| ReaderAdapter | 目录、正文、阅读位置、章节跳转 | 模型推断人物身份 |
| ConfigService | 配置加载、校验、有效配置、版本、脱敏 | 根据显示名猜模型或音色 |
| SourceNormalizer | 不可变原文、片段 ID、原文位置映射 | 润色、摘要替换正文 |
| ChunkPlanner | 语义边界、长度预算、只读重叠 | 硬切后直接假定一句一个说话人 |
| ContextBuilder | 角色检索、场景状态、最近对白、全部可选音色 | 把未提交草稿冒充已确认记忆 |
| TextModelAdapter | 原生结构化请求、完成状态和能力适配 | 用正则从普通聊天文本抓 JSON 兜底 |
| IdentityCoordinator | 按序归一、别名复核、音色首次绑定 | 长时间持有数据库事务等待网络 |
| ManifestBuilder | 原文范围到角色、音色、合成单元的映射 | 使用模型重新生成的正文 |
| JobScheduler | 持久队列、优先级、限流、租约、背压 | 在 UI 主线程执行网络或解码 |
| TTSProviderAdapter | 精确模型/音色路由、能力检查、音频请求 | 在不支持时把控制词拼进朗读正文 |
| AudioCache | 完整性、原子落盘、复用、容量清理 | 暴露半写文件给播放器 |
| PlaybackCoordinator | 当前会话、顺序、预缓冲、暂停、seek、进度 | 自动跳过缺失台词 |
| Diagnostics | 必要状态、错误、时延、缓存指标 | 默认记录密钥或小说全文 |

实现为现有项目中的模块即可，不要求把每个模块拆成服务。首版只为当前活动书籍主动预取；其他书的持久数据保留，未指定继续制作时不继续消耗其接口额度。

## 3. 标识、数据模型与数据库约束

### 3.1 音色标识

配置层级：TTS 供应商 → 模型配置 → 音色配置。

| 标识 | 作用域 | 说明 |
|---|---|---|
| provider_id | 本配置全局唯一 | 应用内部供应商主键 |
| model_key | 同供应商内唯一 | 应用内部模型配置主键 |
| model_id | 远端 API 原值 | 如 X 或 x；按原值作为请求 model |
| voice_profile_id | 本配置全局唯一 | 角色绑定的对象，不受显示名影响 |
| voice_id | 所属远端模型的原值 | 如 Y 或 y；按原值作为请求 voice |

示例中必须正确解析：

| voice_profile_id | provider_id | model_key | 远端 model | 远端 voice |
|---|---|---|---|---|
| vp_a_X_Y | tts_provider_a | a_model_upper_x | X | Y |
| vp_a_X_Z | tts_provider_a | a_model_upper_x | X | Z |
| vp_a_x_y | tts_provider_a | a_model_lower_x | x | y |
| vp_a_x_Y | tts_provider_a | a_model_lower_x | x | Y |
| vp_b_narrator | tts_provider_b | b_narration_model | 用户填写 | 用户填写 |

使用 voice_profile_id 查索引，再找到供应商、model_key 和远端值；不得仅用 voice_id 建全局字典。数据库标识比较采用大小写敏感语义，必要时使用对应数据库的二进制比较或规范序列化后的哈希。规范序列化只排序对象键，不修改字符串值大小写或 Unicode 内容。

同一远端 model/voice 允许存在多个不同参数的配音预设，但必须拥有不同 voice_profile_id。完全重复的有效预设可以提示重复，不能据此合并角色。

### 3.2 最小持久化实体

名称可适配现有代码，但下面信息和约束不得丢失。

| 实体 | 关键内容及约束 |
|---|---|
| BookRevision | book_id、原始文件哈希、正文哈希、解析规则版本；正文改变后产生新 revision |
| SourceUnit | book_revision、chapter_id、paragraph_id、unit_id、顺序、原文、源定位；ID 在版本内固定 |
| AnalysisChunk | 目标 unit 范围、只读前后文、章节/场景引用、规划版本 |
| BookAudioConfig | 本书勾选音色、旁白、策略、cast_revision；新书由 book_defaults 初始化 |
| Character | 书内永久 ID、名称、属性证据、首次位置、状态、角色版本 |
| AliasEvidence | 别名文本、所属角色、关系/场景/时期作用域、证据 unit_id、状态 |
| IdentityChange | 提议、合并、拆分、旧映射、新映射、生效范围、操作者、原文证据 |
| VoiceBinding | book_id + character_id 唯一；voice_profile_id、绑定版本、手动锁定标记 |
| MemoryCheckpoint | 已按序确认到哪个位置、父检查点、上下文版本/哈希、场景状态、近期对白、角色版本、摘要 |
| AnalysisDraft | 候选 JSON、任务输入版本、使用的角色快照、验证状态 |
| Allocation | unit 范围、类别、角色引用、allocation_status、speaker_resolution、fallback_voice_profile_id、证据、分配版本 |
| AudioSegment | 单调顺序、原文范围、绑定/清单版本、render_spec_hash、状态 |
| AudioAsset | request_key、内容哈希、文件路径、格式、真实时长、字节数、校验状态、访问时间 |
| PlaybackManifest | 某书/范围的有序 AudioSegment 引用及 manifest_revision |
| Job | 稳定任务键、类型、状态、优先级、attempt、租约、fence、依赖、输入版本 |
| PlaybackCursor | 书籍版本、原文位置、片段 ID、片内时间、对应音频版本、播放倍速 |

音频文件不直接塞进数据库。正文、角色、清单、任务与音频元数据必须能够在重启后恢复。

### 3.3 区分版本与令牌

| 名称 | 变化原因 | 用途 |
|---|---|---|
| book_revision | 正文或解析规则改变 | 避免旧偏移对应新正文 |
| registry_revision | 角色、别名、身份证据改变 | 识别候选结果使用的旧记忆 |
| binding_revision | 某角色实际配音改变 | 精确失效该角色相关片段 |
| cast_revision | 本书配音方案改变 | 校验目录和绑定依赖 |
| analysis_run_revision | 模型/提示规则/Schema 改变并选择重新分析 | 区分分析运行；不自动抹掉手动绑定 |
| manifest_revision | 已确认配音清单发生改变 | 阻止旧结果挂到新清单 |
| playback_epoch | seek、换书、重新建立播放会话 | 阻止旧回调控制当前播放器 |
| job.fence | 任务重新认领或撤销旧执行权 | 阻止失去租约的 worker 回写 |

registry_revision 变动不是“所有结果和缓存全部作废”的理由。应检查相关角色和来源依赖，必要时局部复核。playback_epoch 也不是音频内容的身份，不应加入可共享音频的内容缓存键。

## 4. 配置契约与 config.example.json

配套 JSON 是合法的标准 JSON，不带注释、不带尾逗号。说明写在本文件，不能往 JSON 塞伪注释字段。实施时生成 config.schema.json，并将它作为加载校验与测试的共同依据。

### 4.1 加载流程

1. 读取用户指定的 config.json；相对路径以该文件所在目录解析。
2. 拒绝重复 JSON 键，避免后一个值静默覆盖前一个值。
3. 检查 schema_version；不支持的版本给迁移提示，不猜测解释。
4. 做类型、范围、枚举、未知字段校验；未知字段报出路径，避免拼写错误被忽略。
5. 建立 provider、model、voice_profile 的索引，检查唯一性和引用完整性。
6. 仅在功能启用或用户主动连接测试时解析本次活动资源的密钥：api_key_env 非空时从该环境变量读取，缺失则报错，不回退到明文；为空时使用 api_key。功能关闭时只校验字段类型和环境变量名称，不要求实际变量存在；未被本书选中且未接受连接测试的供应商不阻塞本书。
7. 模板占位值可以在 feature_enabled=false 时被加载和编辑，但不能发出真实请求。
8. feature_enabled=true 时，活动文本模型、所选音色和旁白涉及的配置必须完整，且不能含已知占位端点或占位 ID/密钥。
9. 对有效配置产生不可变运行快照和必要哈希，再启动队列。
10. 不自动探测所有未启用供应商，也不通过枚举模型名称推断能力。

若使用无认证本地兼容服务，可将 api_key 设为空、api_key_env 设为 null；适配器不发送 Authorization。需要认证的服务仍由连接测试验证。api_key 中出现真实字符串时按敏感字段处理，不写日志、提示词或缓存键。

供应商 URL 组装必须保留 Base URL 的路径：例如 base_url 结尾为 /v1，endpoint 为 /audio/speech，应得到 /v1/audio/speech。不得用会把前导 / 解释为主机根目录的默认 URL 拼接行为丢掉 /v1。移除边界多余斜杠即可，不更改远端模型和音色字符串。

占位值识别针对 REPLACE_WITH_ 前缀和示例保留域名等明确模板值；不能把 X、x、Y、y 这样的大小写演示值一概判为非法，因为真实供应商也可能使用这些标识。不得根据模型名称猜测其是否存在。

### 4.2 结构化输出配置

| 字段 | 语义 |
|---|---|
| text_analysis.adapter | 首版实现 openai_chat_completions；其他适配器必须注册后才能使用 |
| structured_output.mode | json_schema 为默认；vendor_native 仅在已实现供应商原生协议适配器时允许 |
| schema_name_prefix | 每种任务以此生成稳定、符合接口限制的 Schema 名称 |
| strict | 默认 true；要求适配器使用供应商支持的严格模式 |
| vendor_adapter_id | vendor_native 时必须指向已注册适配器；默认 null |
| allow_prompt_only_fallback | 必须 false，不允许运行时改成提示词 JSON 兜底 |
| output_limit_parameter | 根据供应商选择已支持的 max_completion_tokens 或 max_tokens；只发送一个 |
| temperature | 数字时发送；null 时不发送。不支持该参数的模型应设置 null |
| extra_body / extra_headers | 供应商额外参数；经过字段限制后才能发送 |

OpenAI Chat Completions 默认映射为 response_format.type=json_schema，完整 Schema、名称和 strict 放入 response_format.json_schema。供应商自称支持 json_format 时，应实现明确适配器映射，不把这个字段当成全行业通用字段。[S1]

vendor_native 可以是供应商原生 Schema 或原生 JSON 模式，但必须满足：接口参数真实生效、无需靠提示词要求 JSON、返回后做本地 Schema 校验。若仅保证 JSON 可解析，能力报告必须明确其不保证 Schema。配置 strict=true 时应拒绝仅有 JSON mode 的适配器，不能伪报严格支持。

普通 OpenAI json_object 模式仍要求上下文中的 JSON 指令，不作为本项目默认“无格式提示词”路径。[S1]

### 4.3 TTS 能力配置

capabilities 是用户声明和适配器验证的能力信息，不是“让服务突然支持某功能”的开关。更换供应商、模型或接口适配器后重新验证。

| 字段 | 要求 |
|---|---|
| max_input_length | 正整数，为该模型真实输入上限；示例 2000 只是占位起点 |
| input_length_unit | 首版支持 unicode_codepoints、utf8_bytes、tokens；tokens 必须有适配器对应的可靠计数器，否则配置失败 |
| supports_instructions | false 时不发送 instructions，用户填非空指令应报配置冲突 |
| supports_speed | false 时不发送 speed；非默认速度需明确提示并拒绝不支持的配置 |
| supported_audio_formats | 只能选择其中的 audio_format，并检查当前播放器可解码 |
| response_transport | 首版为 binary，完整二进制文件响应；其他传输需要额外已注册实现 |
| supports_word_timestamps | 首版默认 false；设置 true 不能使标准接口自动产生时间戳，必须有适配器实际解析支持 |

OpenAI Speech 的 model 和 voice 独立；instructions、流式格式等能力存在模型差异。[S2] 首版采用完整文件缓存后播放，以便稳定复用、验证和恢复。文本模型的 response_format 对象与 Speech 的 response_format 音频格式字符串不得混淆。

TTS 请求的受保护字段：model、voice、input、response_format、speed、instructions、stream_format。模型级和音色级 extra_body 可以合并扩展参数，音色级覆盖同名的非保留扩展参数，但任何一层都不得覆盖受保护字段。有效扩展参数必须参与渲染指纹。

文本请求的受保护字段：model、messages、response_format、stream、max_completion_tokens、max_tokens、temperature，以及当前适配器识别的其他预算别名。保护集合由公共保留字段与当前 adapter 的全部协议保留字段合并产生；供应商原生 json_format 等实际格式路径及其 schema、strict 控制对象也受保护。extra_body 无权另设一个预算别名或覆盖原生输出控制。extra_headers 禁止覆盖 Authorization、Host、Content-Type、Content-Length 等受管理字段。适配器应采用允许的扩展字段清单；拒绝未知适配器和配置中的可执行代码。

### 4.4 配音方案策略

selected_voice_profile_ids 是“人物候选池”；narrator_voice_profile_id 单独选择，不要求包含在前者中。传给模型的目录为人物候选池与旁白的去重并集，并明确每个条目的用途。

- allow_voice_reuse=true：允许不同角色固定使用同一音色。
- reserve_narrator_for_non_dialogue=true：旁白不能被正常新人物绑定选中；审查后的未确定对白兜底是明确例外。
- unknown_gender_policy=prefer_neutral_then_selected：优先中性音色；没有时从候选池选合适音色，但角色性别仍保留 unknown。
- known_gender_no_match_policy=prefer_neutral_else_require_selection：人物性别已明确却没有匹配音色时，优先所选中性声；仍无候选则等待用户明确选择，不自动进行相反性别配音。
- unresolved_dialogue_policy=narrator_fallback_after_review：复核仍无法确认说话人的单句，可用旁白兜底并保留未确定对白标记。
- identity_conflict_policy=pause_affected_range：两个已绑定角色发生相互矛盾的身份归并时，不静默选择一个覆盖。
- thought_and_quoted_text_policy=narrator：非直接发言统一旁白。
- missing_voice_policy=pause_until_reconfigured：模型/音色不存在、被禁用或缺少有效配置时等待修复，不自动换人声；临时网络失败另由 retry 处理。
- middle_start_policy=build_prefix_identity_first：从中间首次起听先补前缀角色记忆，具体见第 7 节。

上述策略首版只需实现示例使用的值。没有实现的枚举值不能在 UI 中假装可用；以后扩展时必须同步 Schema、代码和测试。

### 4.5 其余运行字段

| 配置组 | 字段及语义 |
|---|---|
| storage | state_store 默认为 sqlite；database_path 为状态库，audio_cache_dir 为音频根目录，temp_dir 与音频目录必须位于支持原子重命名的同一文件系统 |
| text_analysis 限额 | max_concurrency 为所有分析和复核共享并发；reserved_reconciliation_slots 为复核保留；requests_per_minute、tokens_per_minute 为该提供方总预算，null 表示未配置本地限额 |
| text_analysis 预算 | context_window_tokens、max_output_tokens 是配置的模型预算；必须预留输出、角色目录与安全余量 |
| providers 限额 | max_concurrency、requests_per_minute 在同供应商全部模型间共享；models[].max_concurrency 是进一步的子上限 |
| analysis_pipeline | 分块 token 目标/上限、前后文 token 数、最近对白轮数、摘要与角色上下文预算、预分析窗口和复核次数 |
| audio_generation | 首播合成目标 40 字符、常规目标 120、上限 350；按句子/说话人切，实际仍受供应商更小上限约束 |
| prefetch | 首播与续播缓冲、水位、跨缺口投机上限、暂停策略、受支持后台执行 |
| playback | 本地倍速、音调保持、片段级高亮、光标保存间隔、跨章续播、缺口等待 |
| cache | 容量、淘汰目标、磁盘空闲保留、LRU、近期播放保护、复用校验和残留文件清理 |
| jobs | 租约、心跳、轮询兜底和 seek 后取消无用请求的策略 |
| retry | 最多 3 次尝试，包含首次；指数退避、随机扰动、Retry-After |
| observability | 日志级别、全文/原始返回记录开关、调试载荷保存天数、本地指标 |

范围校验：0 < target_chunk_tokens <= max_chunk_tokens；0 < low_water_seconds < target_buffer_seconds <= high_water_seconds；0 < heartbeat_seconds < lease_seconds；0 < evict_to_ratio < 1；0 <= reserved_slots < max_concurrency；所有并发、队列长度、超时为正数。并发设为 1 时保留席位必须为 0，UI 可联动调整，手工配置不合法时显示字段错误。补缓冲和首播秒数不得超过高水位。

audio_generation 中所有 *_characters 按 Unicode 码点计数，不是 JavaScript UTF-16 code unit。供应商 max_input_length 则独立按照其 input_length_unit 计数，可以是码点、UTF-8 字节或 token；两项限制分别检查，不能直接对不同单位的数值取最小值。跨前后端统一实现并覆盖表情、组合字符和中英文混排测试。

keep_all_selected_voice_profiles_in_system 必须 true。角色档案可以按预算检索，勾选音色目录不允许静默裁剪；目录过大时报告配置预算不足。

## 5. 原文标准化、定位与分块

### 5.1 固定正文版本

复用现有阅读器抽取逻辑。EPUB 依据 spine 阅读顺序，不按压缩包文件名排序。[S3] TXT 复用现有编码处理和章节识别。

标准化只做明确、可追溯的处理，例如换行统一。保留正文与阅读器原始位置的映射。脚注、目录、标题、插图说明是否朗读由现有阅读器或明确导入规则决定，并形成版本；模型不能临时删掉内容。

相同文本在书中出现两次必须有两个不同位置 ID，不能只用文本哈希作为 unit_id。可使用“书籍版本 + 文档/章节位置 + 局部序号”或稳定 UUID。模型不会生成这些 ID。

### 5.2 原文片段

先按段落、句末、引号、叙述插入等边界产生较细 source units。保留原文标点和必要空白。它们是定位单位，不意味着引号内一定是实际说话。

例：

~~~text
u1: “别动。”
u2: 林岚说，
u3: “后面有人。”
~~~

分配为角色、旁白、同一角色。若一个 unit 内仍混有不同说话人，允许模型提出可验证的拆分建议；程序使用原文锚点及受校验的局部范围生成子单元，然后重新分配。不要依赖模型计算整章字符偏移。

子单元修订保留父 ID 和位置来源，原文不改变。受影响的旧 chunk/assignment 标记过期；无关原文单元 ID 保持稳定。

### 5.3 分析块与上下文

优先章节 → 场景 → 段落组 → 完整句。超长章节继续拆块，不把整章大小当作模型必然能够处理的长度。

一个任务明确分为：

- target_units：唯一需要输出的目标范围。
- context_before、context_after：只读相邻原文。
- confirmed_recent_turns：最近已确认的说话轮次。
- scene_state：在场人物、场景变化、未闭合引号或发言状态。
- relevant_characters：相关角色、证据、作用域别名及固定绑定。
- chapter_summary：只来自已确认前沿的摘要。
- pending_identity_questions：待解决的局部身份问题。

总预算 = 业务规则 + 全部启用音色目录 + 角色记忆 + 目标正文 + 前后文 + 输出预算 + 安全余量。超过预算时优先减少目标块，随后缩减非必要背景，不得移除固定绑定、裁剪勾选目录或把完整目标文字截断。没有可靠 tokenizer 时使用保守估算，并在超长请求错误后缩小任务；不能声称估算等于精确 token 数。

相邻块的 target_units 不重叠；前后文可以重叠。只读后文中的角色只能形成证据或待处理提议，不能因其先被看到就越序建立正式人物或提前推进记忆前沿。

## 6. 角色记忆、音色选择与身份修正

### 6.1 角色记忆

角色档案是长期记忆，供应商会话历史不是。每次请求独立组装所需状态，不依赖“模型应该还记得前几次”。

保存姓名、别名作用域、首次位置、性别等属性证据、关系、状态和绑定。不能把他/她写成全书别名；父亲、师父依赖关系对象；黑衣人、老人、皇帝等描述或职位不具有天然唯一性。

相关角色检索至少结合：

1. 当前姓名和称谓。
2. 当前场景和上一已确认场景人物。
3. 最近对白参与者。
4. 关系与别名的作用域。
5. 尚未解决的身份线索。

候选检索没找到，不等于全书不存在。提交任何新角色前要查询完整角色/别名索引，必要时进行局部模型复核。相似名称只能形成候选，不能用字符串近似直接合并。

### 6.2 新角色与首次绑定

模型只能给局部 ref，例如 local:new_1。正式 character_id 由应用在确认后分配。

匹配优先级：用户手动绑定 → 已有正式绑定 → 新人物的合法音色建议。新建议仅从本书人物候选池选择；参考有证据的性别、年龄感与用户音色描述。模型看不到真实声音，不得把标签匹配当试听判断。

优先为经常同场对话的角色使用不同声音；音色不足时允许复用。已锁定角色不能为给新人腾音色而重新配音。没有对应性别的音色不允许调用未勾选音色；可用所选中性声或按配置选择，并保留未知属性，不反推人物性别。

voice_profile 的显示名、备注变化不改变已锁定绑定。实际模型、音色或合成参数变化会产生新的 render_spec_hash，并按第 13 节处理。

### 6.3 无法确认与身份冲突

区分：

- 明确已有角色：复用 ID。
- 明确是新人但不知姓名：创建有场景和首次位置的暂存角色；后续可改名。
- 不知道这句话由谁说：复核后仍不明可临时旁白，保留 dialogue + unresolved，不创建一个全书通用“未知人”。
- 两个已有身份发生矛盾：按 identity_conflict_policy 暂停受影响范围，其他合法分析可继续，但顺序播放不能越过该范围。

max_identity_rechecks 默认 2，是语义复核次数；每次网络调用的失败重试另受 retry 限制。所有调用都占用同一文本模型限额。

旁白兜底只绑定该具体未确定发言，不写入永久人物绑定，不影响后续真实角色识别。UI 应能定位待确认片段，不能悄悄标为已确认。

必须分开“分配决策已接受”和“说话人已识别”：兜底条目为 allocation_status=accepted、speaker_resolution=unresolved、kind=dialogue、speaker_ref=null，fallback_voice_profile_id 为本书旁白。正常旁白为 accepted、kind=narration、speaker_ref=narrator。上述状态由程序审核后保存，不能由模型自行宣称通过。

TTS 和缓冲放行条件统一为“Allocation 已接受且实际声音已确定”。本文件的身份确认前沿指身份状态已按序提交，允许携带已审核的未确定事项；不能因 speaker_resolution=unresolved 就永久阻塞已允许的兜底。

### 6.4 合并和拆分

模型提出身份关联证据，应用确认。合并保留原始角色记录、重定向、每条 assignment 的原始来源和可逆修改记录，不做不可恢复的硬删除。

- 只有一方绑定时，沿用已有绑定。
- 双方同声时，归一身份即可。
- 双方异声时，不自动取最近完成的结果；显示冲突，接受明确修正后更新相关引用。
- 错误合并可拆回，恢复受影响 assignment，不重新解析整个书库。
- 手动修正优先于后续自动猜测，除非用户解除锁定。

身份或说话人修正改变某个检查点内容时，自最早受影响位置起沿父检查点和相关角色/场景依赖复核后续检查点、草稿和已确认标注。上下文哈希相同且依赖未变的部分可以保留；不能用一个正文版本正确但人物上下文已过期的检查点从中间起听。单纯改音色不触发人物记忆重建，只有实际分配或声音变化的局部合成单元需要重生成。

后文揭示的隐藏身份可能需要修正已生成的早期内容。边分析边播放无法撤回用户已经听过的声音；此方案保证已确认 ID 的绑定一致，不承诺模型从首句就百分之百认识所有隐藏身份。首版不做“伪装身份声音演出”子系统；最终全书角色归一后可以重建受影响音频。

## 7. 跨章预分析与从中间起听

必须分别维护三种前沿：

1. **连续身份确认前沿**：从书首或有效已存检查点开始，按顺序确认到哪里。
2. **分配完成范围**：哪些 unit 已有有效 assignment，可包含预分析草稿或稀疏已保存范围；草稿不等于确认。
3. **当前播放光标之后的连续音频前沿**：从当前位置往后，连续就绪到哪里。

缓存了很后面的章节，不表示当前位置可播。后一章草稿先完成，也不表示前一章人物状态已经确认。

### 7.1 正常连续播放

以当前已确认状态为基础，并行分析窗口中的块。未来块可使用较旧快照生成候选，但必须在其轮到提交时补足前文记忆。当前块的场景状态只由已确认内容推进。

前章最后一个块和后章第一个块保留邻接原文。章节变化不重置角色表、音色、场景连续发言；明确场景切换后再更新局部在场人物。

不要求整章全部完成后才开始听。最前面一组原文已确认、TTS 片段已验证且满足启动条件即可播放，其余内容继续准备。

### 7.2 从未分析的中间章节起听

默认使用 build_prefix_identity_first：

1. 检查目标之前最近的有效 MemoryCheckpoint。
2. 若已具备前缀角色状态，直接分析目标附近并准备音频。
3. 若缺失前缀，优先补齐从检查点到目标的身份分析；无需合成这些前文音频。
4. 可以并行提取前缀块候选，但按序确认不能跳过。
5. 显示“正在补齐前文人物档案”，展示真实进度，允许用户继续普通阅读或普通单声听书。
6. 未补齐时不得宣称目标章已经具备全书一致的多人配音。

首版使用同一分析器处理前缀，不额外制作低质量的“只扫名字”捷径。已有索引可复用，未来可优化专门的人物预扫描，但需要同等证据和覆盖验收。

### 7.3 回跳、换书与旧结果

回跳可以复用缓存和已有身份。用于理解该位置的场景状态读取当时检查点；全书已经确认的音色绑定仍保持当前版本。界面显示的剧情摘要不展示未读后文，分析过程中的长期身份信息也不得混入可朗读正文。

seek 增加 playback_epoch、重建目标播放队列和预取优先级，不清空角色库或通用音频缓存。换书停止旧书的新预取，在途结果按有效租约和依赖决定是否保留缓存。

## 8. 文本模型协议与有序确认算法

### 8.1 输入规范

系统消息包含：任务规则、全部选中人物音色及固定旁白、每个音色的内部 ID、远端模型/音色标识、名称、性别、备注、用途；已有角色固定绑定以只读约束提供。无密钥和服务地址。

书籍正文以独立的数据区域/用户消息传入；小说中的命令和文本不能改变系统规则。用户填写的备注也作为音色描述数据，不能成为可执行指令。

请求元数据由程序保存：job_id、chunk_id、book_revision、源哈希、registry_revision、cast_revision、analysis_run_revision、Schema/规则版本。模型返回同名值也不作为提交依据。

### 8.2 分配输出契约

实现严格 Schema，所有对象禁止未定义字段，所有定义属性列入 required；可空值显式为 null。首版根对象：

| 字段 | 内容 |
|---|---|
| assignments | source_unit_ids、kind、speaker_ref、evidence_unit_ids、evidence_type |
| new_character_proposals | local_ref、display_name、gender、suggested_voice_profile_id、evidence_unit_ids |
| identity_link_proposals | from_ref、to_ref、evidence_unit_ids、relation_type |
| unresolved_items | source_unit_ids、candidate_speaker_refs、issue_type |

kind 枚举 narration、dialogue、inner_monologue、quoted_text。quoted_text 指书信、屏幕文字、嵌套转述等没有当前直接发言者的引用内容，不泛指所有带引号的文字；普通直接对白仍为 dialogue。gender 枚举 male、female、neutral、unknown，人物属性和音色性别标签不能互相推导。

speaker_ref 为 narrator、已提供的正式角色 ID、已声明的 local:new_*，或未确定对白的 null。非直接发言根据本书策略固定 narrator。evidence_type 至少区分 explicit_attribution、confirmed_continuation、context_inference、unresolved；不以模型自报的 0.99 作为校准概率。

identity_link_proposals 首版 relation_type 为 same_person_candidate，只有提议作用。未充分证实时保持空数组。系统不能要求模型无论如何给出确定说话人。

示例，输入 u1=林岚问：，u2=“你终于来了？”，u3=年轻男子陈舟答道：，u4=“我来晚了。”；林岚已有角色 char_001：

~~~json
{
  "assignments": [
    {
      "source_unit_ids": ["u1"],
      "kind": "narration",
      "speaker_ref": "narrator",
      "evidence_unit_ids": ["u1"],
      "evidence_type": "explicit_attribution"
    },
    {

      "kind": "dialogue",
      "speaker_ref": "char_001",
      "evidence_unit_ids": ["u1"],
      "evidence_type": "explicit_attribution"
    },
    {
      "source_unit_ids": ["u3"],
      "kind": "narration",
      "speaker_ref": "narrator",
      "evidence_unit_ids": ["u3"],
      "evidence_type": "explicit_attribution"
    },
    {
      "source_unit_ids": ["u4"],
~~~

已有角色的 assignment 不含可重选 voice 字段。speaker_ref 的引用一致性、角色池动态枚举和来源范围由 Schema 与应用共同校验；局部临时 ID 不做全书 ID。

身份复核使用独立 Schema，输入争议片段、候选角色和证据，输出 resolved_existing / confirmed_new / unresolved / conflict、引用及证据。摘要更新使用独立 Schema；摘要只辅助上下文，不改变配音绑定。可以由同一模型完成，不需要多个模型服务。

### 8.3 有序提交算法

1. Scheduler 在预算内为多个 chunk 创建候选分析任务；任务带输入版本。
2. 对完成响应先检查 HTTP、完成状态、拒绝、截断，再解析和校验结构。错误结果不得进入正式状态。
3. 草稿暂存，提交器只取连续身份前沿的下一块。
4. 查询最新角色库和别名作用域，解析 existing/local 引用，检查此前新建立的身份。
5. 对基于旧记忆的歧义做局部复核。必要时只重分析受影响原文，不无条件重做整章。
6. 检查音色建议是否合法。已有绑定必须复用；确属新人才建立绑定。
7. 复核调用在数据库事务外完成。
8. 开短事务，再次检查本块输入、相关依赖版本与提交权；若变化则重新确认，不能盲写。
9. 原子提交角色/别名、绑定、Allocation 和 MemoryCheckpoint，并推进连续前沿。
10. 事务成功后发布幂等的“确认结果可用”事件。只有与当前播放需求及音频预取窗口相交的已接受 Allocation 才创建 manifest/TTS 准备任务；前缀补齐只保存分析与人物状态，不合成前文音频。崩溃恢复按当前需求重建缺失任务。

单本书的身份提交器是单写者；多进程环境通过数据库认领/锁和版本条件保证，不仅靠某个进程内 mutex。不同书可以独立提交，但共享供应商限额仍需统一。

### 8.4 校验

- 目标 unit 每个恰好出现一次；顺序、范围无遗漏无重叠。
- 模型引用的 evidence 可以来自目标或已提供只读上下文，但 assignment 只能来自目标。
- 同一 assignment 的 unit 必须连续，不能把中间另一个人的句子跳过去拼到一起。
- 按分配顺序拼回原文，与目标规范化原文完全一致。
- 所有正式角色存在，局部角色唯一且可解析。
- 所有音色来自该书有效目录，固定绑定不能被覆盖。
- 已取消的运行或过期正文/Schema 结果不能提交。
- 结构正确但身份冲突仍需复核，不能用 JSON 校验通过替代语义校验。

不修补半截 JSON 的括号后继续使用。输出截断时缩小块或调整允许的输出预算后重试；模型明确拒绝、配置不兼容等确定性错误显示原因，不进行无意义循环。

## 9. 后台调度、预分析与背压

### 9.1 一个权威调度器

所有阅读页面、设置页和播放面板都调用同一个 Scheduler，不各自创建循环。单进程可使用统一服务对象；多窗口/多进程使用现有协调机制及数据库所有权。持久任务必须能被新进程恢复。

任务先检查依赖是否满足，再竞争并发和限流额度。不能先占用 TTS 全局执行槽，再等待一个已满额供应商，否则其他供应商会被不必要阻塞。统一调度器应只为“全部必要额度都可取得”的任务分配执行权，失败时释放已取得令牌。

### 9.2 优先级

从高到低：

| 优先级 | 任务 |
|---|---|
| P0 | 新播放位置所需的前文身份依赖、身份复核、第一段音频、当前首个缺口 |
| P1 | 当前游标后用于补齐低水位的文本确认和 TTS |
| P2 | 补齐目标缓冲的后续已确认片段 |
| P3 | 当前章剩余部分及后 3 章的候选分析 |
| P4 | 空闲清理、诊断整理、低优先级维护 |

同优先级优先已满足/正在解除提交依赖的任务，再比较原文距离。前缀补齐必须从下一可提交块向前推进，该块及其重试优先于更接近播放目标的未来块；不能先把候选窗口塞满后部前缀块而让第一块永远无法派发。前缀身份补齐属于 P0，但不要占用全部复核席位后使提交器永远无法前进。

文本并发 4 包含保留的 1 席，不是 4+1。首版保留席位不借给低优先级候选分析，避免当前身份问题被未来块堵住。TTS 供应商前台保留席位同样包含在其上限内；常规预取不能占满这些席位。并发=1 时用优先队列处理，保留席位为 0。

同一供应商的模型 X 和 x 共享供应商 semaphore、RPM 和冷却状态；各自 model.max_concurrency 只能继续收紧。复制供应商条目不是绕过同一账户真实限额的方法；实际服务共享账户额度时应整合配置或在适配层共享真实账户限流，不声称每个 model 都有一份完整额度。

### 9.3 章节窗口与队列边界

ahead_chapters=3 限制可以前瞻到的章节，不要求一次发出所有章节任务。max_ahead_chunks=24 限制相对当前提交前沿的分析计划窗口；max_uncommitted_chunks=8 限制运行中和已完成但尚未有序提交的普通候选块数量，复核不受该数量锁死，但仍受总并发限制。

超长当前章节可能占满块窗口，后章稍后进入；极短章节可能在窗口内不足以提供 300 秒缓冲，此时接受较低缓冲，不擅自扩成整书分析。

一旦到达计划窗口或待提交上限，停止新增候选，等待有序提交释放空间。首个身份冲突持续存在时，已完成后续候选最多保留有界窗口。

候选块从首次派发到提交或明确废弃，持续占用一个未提交窗口位置；retry_wait 不释放该位置，既有槽位的重试可以重新执行。Scheduler 为下一可提交块优先分配位置，防止它在重试期间被后续候选挤走。

TTS 只为已接受分配且实际声音明确的范围创建任务（含按策略审核的未知对白兜底），且同时受以下约束：

- 全局和供应商、模型并发。
- 每分钟请求与令牌预算。
- max_pending_jobs=64。
- 首个音频缺口之后最多 8 个已创建未消费的投机合成单元。
- 目标/高水位。
- 章节分析窗口和身份确认前沿。
- 缓存空间与在途写入预留。
- 暂停、停止及平台后台权限状态。

不要一次将全书所有台词物化成 TTS 请求。

### 9.4 连续可播缓冲

设本地播放倍速为 r，当前音频剩余媒体时长为 d0，后面连续有效音频时长为 d1...dk：

~~~text
continuous_ready_seconds = (d0 + d1 + ... + dk) / r
~~~

遇到第一个缺失、损坏、版本失效、分配未接受或尚未生成的片段即停止累计。已接受的未知对白兜底在音频验证后正常计入，不要求将人物身份改成“已识别”。

以下不计入连续可播时长：在途请求、半写文件、字数估计时长、缺口后面已经完成的音频、旧绑定音频。

新请求预算可以使用 estimated_pending_seconds。初始估算采用 audio_generation.initial_estimated_characters_per_second=4.0，之后按音色实际“文本长度/合成音频时长”做平滑估算。它只用于控制预取，不能显示成真实可播时间，也不能当精确字级时间戳。

低于 90 秒提高 P0/P1；常态补到 300 秒停止新增普通 TTS；600 秒是包括在途估计的高水位保护，避免过多请求已发出。实际生成时长可能超过估计，已完成文件可以保留，但停止新增直到回落。

如果前方一直有缺口，连续可播永远很低，也不能无止境向后发请求。8 个片段限制、64 个任务限制、预计覆盖水位和空间预算必须共同生效。

### 9.5 启动与恢复

进入本书沉浸式听书后才启动该书的主动分析与合成；普通阅读不自动上传整本书分析。

第一段的必要身份确认完成后，优先以较小的合成单元准备首播。连续 8 秒就绪即可启动；第一段就绪后经过 3 秒仍未达到 8 秒，可以播放已经就绪的连续内容。没有任何完整音频时绝不能“超时后开始空播”。

续播使用 resume_buffer_seconds；书末剩余有效内容不足该时长时直接播放剩余内容。正常读完一段但下一段未就绪时进入 buffering，保持正确光标，不能把它误判为章节结束。

## 10. 合成单元、音频接口与顺序播放

### 10.1 从 Allocation 到 AudioSegment

1. 按原文顺序读取已确认 Allocation。
2. 从 SourceUnit 取回精确朗读文字，按明确的固定规则处理朗读时不需要发声的标点；保留可逆位置映射。
3. 非直接发言取本书旁白；已确认对白查 VoiceBinding；未确定对白按预设兜底策略处理。
4. 只有连续、实际音色与参数一致、类别兼容的片段可以适度合并。
5. 首版禁止跨角色 ID 合并，即使两个人共用同一个音色；也禁止跨章节合并。
6. 按完整句子和停顿拆分长文本，不能为了达到目标字符数拼过另一个角色或旁白。
7. 目标 120 字符，上限 350；首播目标 40。短对白不强行补长或改写，单句超过限制再按更小语义边界切分。
8. 同时满足应用字符上限和供应商真实输入上限；若供应商按字节或 token 限制，分别计数并缩小到两项均满足，不能跨单位直接比较大小。输出预算、格式限制也必须遵守。

首版保存完整音频后播放，不将不完整响应发布到缓存。未来支持流式首播需要单独设计“临时播放流”和“完整可复用资产”的状态，不能直接把半文件标 ready。

### 10.2 精确路由

调用适配器前固化 RenderSpec：

~~~text
provider_id
provider endpoint / adapter version
model_key
exact model_id
voice_profile_id
exact voice_id
exact input text
effective audio_format / speed / instructions / extra_body
render_spec_hash
~~~

OpenAI Speech 将 model_id 映射为 model、voice_id 映射为 voice、正文映射为 input、audio_format 映射为 response_format。instructions=null 时省略字段，不发送字符串 "null"。不支持 speed 且值为 1.0 时可省略；非默认速度与不支持能力冲突时拒绝配置。

请求成功必须验证可解码音频；HTTP 200、非空字节或正确后缀不足以判 ready。供应商返回 JSON 错误体、HTML 或损坏音频时进入错误处理。

### 10.3 顺序播放器

PlaybackManifest 是唯一顺序来源。每个播放项带原文顺序、manifest_revision、request_key 和 AudioAsset 引用。

- 合成按 3、1、4、2 完成，仍只能播放 1、2、3、4。
- 音频 ready 事件只通知“重新检查需求”，不能直接无条件 enqueue。
- 入队校验 book_revision、当前 manifest 项、request_key、playback_epoch。
- 同一播放项不能因重试成功事件重复入队。
- 一个片段未就绪，继续播放此前连续缓冲，随后等待；不得跳过。
- 跨章按现有目录顺序前进，下一章未就绪时显示准备状态，不重复上一章最后一段。

多供应商音频由现有播放器逐段解码播放。不要直接拼接 MP3 字节当作可靠章节音轨。首版不做章节导出或混音，避免扩大范围。

### 10.4 进度、倍速与高亮

保存原文位置 + 当前 AudioSegment + 音频版本 + 片内时间。按 cursor_save_interval_ms 定期保存，并在暂停、seek、切书和生命周期事件上立即保存。

同一个音频资产恢复时可以使用片内时间。角色音色或合成单元变更后，新音频时长可能不同，此时恢复到对应原文片段边界，不把旧秒数机械复制到新音频。

default_rate 是播放器倍速，与 TTS render_settings.speed 区分。调整播放器倍速不重新合成，只更新连续缓冲秒数。preserve_pitch 交由当前播放器能力实现；不支持时明确其实际行为，不假报已支持。

没有供应商真实时间戳或独立对齐能力时，只做 audio_segment 级高亮。合并了多个 source units 的一个音频段，就高亮对应整体范围；不能按字符长度均分音频时长并声称逐字同步。

## 11. 音频缓存、原子写入与空间管理

### 11.1 请求键与资产键

request_key 用于判定“同一有效合成请求”，建议为规范序列化输入的 SHA-256，包含：

- 应用用户/账户隔离范围。
- 供应商实例与影响路由的端点、适配器版本。
- 精确 model_id、voice_id。
- 精确 TTS input。
- 有效音频格式、合成速度、指令、扩展请求参数。
- 影响音频文本的预处理规则版本。

影响路由、协议版本或音频结果的非敏感扩展请求头也进入有效指纹；认证秘密不进入指纹。使用扩展头改变真实租户或账户时必须建立相应的新供应商实例身份。

不要将明文密钥写入缓存键、文件名或日志。密钥轮换默认不导致音频失效；切换为不同真实账户/租户时应建立新的供应商实例身份，避免跨账户错误复用。

不要加入全局 registry_revision、播放 epoch、当前时间、角色显示名或仅用于挑选的备注。这些不会改变实际合成请求。声线相同但角色不同可以共享同一内容资产，播放清单的角色身份仍独立。

AudioAsset 另有实际文件内容哈希。request_key 是请求到资产的索引，不能把它当作允许多个 worker 覆写的文件名。

### 11.2 文件写入流程

1. 用 job_id + attempt/fence + 随机后缀创建独占临时文件。
2. 接收完整响应，限制异常过大响应；检查 HTTP 和供应商错误。
3. 解码检查格式、实际时长和可用性，并计算文件哈希。
4. 使用内容哈希或唯一不可变资产路径，在同文件系统完成原子重命名。
5. 开事务校验任务 owner/fence、有效租约、输入版本和发布条件。
6. 在同一事务内保存 AudioAsset 元数据、发布 request_key 索引、将逻辑任务设为 succeeded，并把仍匹配输入与版本的清单项标记为 ready。当前清单已变化时，只发布合法通用缓存及任务成功状态，不挂到错误清单。
7. 事务成功后仅发送通知，不再分步写入上述正式状态。

旧 worker 即使迟到写完独立资产，也不能覆盖新 worker 的文件或数据库索引。失去 fence 的结果只能成为可清理的孤立文件，不能使正式任务成功。

文件已落盘而事务失败时最多留下孤立文件；不采用“先在数据库标 ready，再慢慢写文件”的顺序。启动后扫描并核对必要残留，清理无引用且不属于有效租约的孤立资产。

### 11.3 复用检查与损坏恢复

复用前检查文件存在、元数据和校验和；按 verify_checksum_on_reuse 执行完整校验。文件损坏、无法解码或路径丢失时，只失效该资产引用并重建其 request_key。

缓存是否仍可用与历史任务是否成功必须分别判断。有新的有效播放需求时，即使同一 request_key 的任务历史上 succeeded，只要资产被淘汰、缺失或损坏，也要通过原子状态转换重新排队、递增执行代次并建立本轮尝试预算，保留历史记录。cancelled 的逻辑任务重新被需要时也可以恢复。单纯发生 LRU 淘汰不立即重新合成，以免清理后自动填回。

播放器已经持有的资源有引用保护。清理器不得删除正在使用、仍被队列或解码器持有的文件。

读者必须在文件校验、打开、解码或入队前原子取得资产保护；清理器通过同一协调机制仅能把未保护资产置为 evicting。evicting 资产不能再被新读者直接取得。任一方取得所有权后另一方重查状态；读取失败释放保护并执行缺失恢复。该保护同样覆盖异步校验和计算，不能留下“检查存在后、保护前”被删除的窗口。

### 11.4 缓存预算

预算包含：已提交文件 + 临时文件 + 在途请求写入预留，而不是只统计数据库 ready 行。多请求并发时先原子预留空间，再发送/落盘，避免各自看到同一份空闲容量。

达到 max_bytes 或实际可用空间不足时，按 LRU 清理未保护资产；目标降到 evict_to_ratio。保留 min_free_disk_bytes；平台无法提供真实磁盘信息时使用平台配额和可观测错误保守限制，并明确能力限制。

保护范围：

- 正在播放及播放器持有的资产。
- 当前恢复所需和近期播放 protect_recent_playback_seconds 的有限范围。
- 少量已入播放队列的前方资产。
- 仍有有效租约的临时文件和写入预留。

历史 PlaybackManifest 的引用不意味着永不淘汰；可以保留元数据并在以后需要时重建音频。缓存状态查询不应刷新最近使用时间，真实播放或显式访问才刷新。

空间不足且无法淘汰时，停止新预取并提示原因，优先保留正在播放的内容。不能为追求 300 秒缓冲删除当前音频。临时文件清理阈值到达时也必须排除仍有效的任务。

## 12. 持久任务、恢复、取消与失败

### 12.1 任务状态

推荐通用状态：

| 状态 | 含义 |
|---|---|
| queued | 等待依赖、限额或调度 |
| running | 已原子认领，持有租约和 fence |
| retry_wait | 临时错误，等待 not_before |
| succeeded | 本逻辑任务输出已验证并正式保存 |
| blocked | 配置、身份冲突、空间或人工处理问题 |
| failed | 自动尝试耗尽，等待显式重试 |
| cancelled | 此逻辑任务不再需要或已被新输入替代 |

模型候选 succeeded 只表示草稿有效保存，不等于身份已提交，更不等于音频 ready。各阶段分别保存完成状态。

### 12.2 幂等键与认领

分析任务键至少包含正文/分块输入、分析运行/Schema 版本和任务种类；候选依赖的具体上下文以输入哈希记录。身份复核另有争议范围与最新依赖键。TTS 的逻辑任务键由 request_key 决定。

对逻辑任务建立唯一约束，同一输入不能因多个页面反复请求而重复创建。任务创建和状态更新由事务或等价原子机制保证。

唯一约束限制的是一个逻辑任务，不表示它成功后永远不可再次执行。依第 11.3 节进行按需缓存重建或显式重试时复用逻辑任务、开启新的执行代次；并发请求只能有一个成功把它从历史终态转回待执行态。

认领时：

1. 检查 queued/retry_wait 到期或 running 租约过期。
2. 原子设置 lease_owner、lease_expires_at。
3. 递增 fence，并记录此次执行值。
4. 只有本次 owner/fence 匹配者可以续租或提交。

lease_seconds=60，heartbeat_seconds=15。心跳独立于网络等待和 UI 主线程。请求 deadline 仍为 90 秒分析 / 120 秒 TTS，续租不能把一次接口调用无限延长。

旧 worker 失去租约后不得更改任务或正式文件索引。进程内判断“我没收到取消”不构成有效提交权。

### 12.3 网络错误与重试

max_attempts=3 包含首次。临时网络错误、429、可恢复服务端错误按指数退避和抖动重试，尊重 Retry-After。供应商级限流应让该供应商共享冷却，不让其多个模型同时重试冲击接口。

认证失败、模型或音色不存在、原生输出配置不支持、确定性额度不足等进入 blocked，等待修复。不要对无效 Schema 或已禁用音色反复重试。

超时后远端可能已经执行并计费；本地幂等只能保证不重复发布，不保证供应商恰好调用一次。只有适配器实际支持且验证过供应商幂等机制时才能使用其保证，不能凭空添加一个请求头就宣称解决。

### 12.4 暂停、停止、seek

- 暂停：立即停播放器、保存位置、停止新分析和 TTS；在途可完成缓存。暂停状态持久保存。
- 恢复：重新评估当前需求和连续可播时长，补齐水位。
- 停止：清理当前播放会话和主动需求，保留角色、确认结果和缓存。
- seek：增加 playback_epoch，重建目标需求；旧窗口排队任务退出主动调度；根据 cancel_unneeded_requests_on_seek 尝试取消无用在途请求。
- 取消是尽力操作，不能假定供应商一定停止。晚到结果仍必须经过 fence 与版本检查。
- 有效旧请求可以写通用缓存，但不得直接控制新 playback_epoch 的播放器。

playback_epoch 不代替 job.fence。前者保护播放会话，后者保护任务发布，两者必须独立验证。

### 12.5 应用生命周期

“后台”表示在平台允许的后台执行环境中工作，不表示进程关闭后仍可无条件运行。

- 桌面：使用现有后台服务/进程/线程，避免 UI 阻塞。
- 移动端：复用平台媒体播放和后台任务机制，处理系统挂起、网络变化和存储约束。
- Web：优先复用已有服务端任务能力；若只能在浏览器内运行，明确页面关闭/系统冻结的限制，不能以定时器宣称永久后台执行。
- 进程重启：恢复数据库、处理过期租约、检查缓存残留；用户上次主动暂停则保持暂停。
- 网络恢复或操作系统恢复不能自动把用户暂停状态改为播放。

实施阶段 0 必须依据实际平台记录采用的后台执行方式，并提供对应生命周期验证，不要求用户先决定一种新技术栈。

## 13. 配置变更、失效范围与手动修正

### 13.1 配置快照

全局 book_defaults 只初始化新书，修改它不自动覆盖已经开始的书。已开始的书持久保存选中池、旁白、绑定和相关渲染版本。

用户可以对本书明确应用新配置。应用时先计算受影响角色、片段和在途任务，再提交版本更新；不得把每次打开设置页都当作全书重新分析。

| 变更 | 处理 |
|---|---|
| 音色/角色显示名称、普通备注 | 更新展示；备注可影响尚未绑定新角色的推荐，不改变旧绑定或声音缓存 |
| 新增可选音色 | 新角色可选；旧角色保持声音 |
| 移除尚未被绑定的音色 | 更新本书候选池 |
| 移除/禁用已绑定音色 | 保留已有合法缓存可播，未生成部分阻塞；需要明确替代方案，不能重新随机选 |
| 实际 model_id / voice_id / 合成 speed / instructions /有效 extra_body 变化 | 生成新渲染版本，更新所有依赖该音色的受影响合成单元 |
| 更换旁白 | 更新所有旁白及临时旁白兜底片段 |
| 修改某角色音色 | 只更新该角色及合并边界受影响的局部合成单元 |
| 合并角色而有效音色不变 | 更新身份引用，复用音频 |
| 修改正文 | 新 book_revision；重做受影响定位和分析，可复用精确请求仍相同的音频资产 |
| 文本模型/分析规则改变 | 仅影响新任务或明确重新分析范围；手动绑定不被无条件清空 |
| 本地播放倍速变化 | 不重合成，更新水位计算 |
| 密钥轮换 | 不因密钥本身变更清空音频；更新后续请求凭据 |
| 更换供应商真实账户/租户或端点 | 新实例/路由指纹，避免错误跨账户复用 |

已经合并进一个 TTS 请求的多个原文片段，在其中一段改变后可以重建该局部合成单元。无可靠时间戳时不能随意切出旧音频一小段冒充新结果。

### 13.2 播放中修改

正在播放的单元可以在明确提示后播完，并在下一个片段边界切换新清单；用户选择立即应用时则停当前单元并从对应原文边界重新准备。首版可只实现“下一片段生效”的一致规则，不能在音频中途混用新旧片段。

“下一片段生效”的切换点必须是当前旧 AudioSegment 结束后的原文位置。固定并保护正在播放的旧资产，新清单从这个原文切换点重新规划未播放范围，禁止新合成单元跨越切换点。切换时按原文位置找下一项，不沿用旧清单序号；否则旧段覆盖单元 1～3、新段覆盖 1～5 时会重读或漏读。

旧任务可保存其独立资产，但只能挂到仍引用相同 request_key 和有效版本的清单项。修改全局配置不允许旧响应覆盖新绑定。

## 14. 现有阅读器的接入接口与 UI

接口名称可按现有语言调整；优先提供应用内部服务，不为这些方法强制新增 HTTP 服务。

| 操作 | 行为 |
|---|---|
| loadAndValidateConfig | 返回可用性、字段错误、有效配置摘要，不返回明文密钥到普通 UI |
| testAnalysisProvider | 小样本原生 Schema 测试，验证结果实际遵循结构 |
| testVoiceProfile | 精确路由指定配置，短文本合成并验证可播放 |
| prepareBook | 建立/恢复书籍版本、原文单元、配音方案与检查点 |
| startImmersivePlayback | 从原文位置准备所需身份与音频并播放 |
| pause / resume / stop | 执行第 12 节状态规则 |
| seekToSource | 原文定位和新 playback_epoch |
| updateBookVoicePool | 验证新增/移除音色及绑定影响 |
| setCharacterVoice | 版本化修改指定角色声音 |
| resolveIdentity / undoIdentityChange | 合并、拆分、纠正说话人并保留证据 |
| retryBlockedRange | 配置或身份问题修复后重新调度必要范围 |
| getPipelineStatus | 真实前沿、队列、缓存、待复核与阻塞信息 |

### 14.1 必要 UI

1. **供应商与音色设置**：供应商下展示模型，模型下展示音色；显示名称、远端 ID、性别、备注、试听、启用状态。不要把所有音色平铺后丢掉所属模型。
2. **本书配音设置**：人物音色多选、固定旁白、文本模型并发与必要预取设置。
3. **角色列表**：名称、别名、固定音色、确认状态、原文证据入口；可以修正。
4. **播放器**：播放/暂停、章节、倍速、阅读高亮和真实准备状态。
5. **任务与错误详情**：字段错误、供应商/模型/音色缺失、待复核、缓存不足和重试入口。

普通用户界面使用“正在识别人物”“正在生成后续音频”“正在补齐前文人物档案”“等待音色配置修复”等可理解描述。数据库版本、fence、Schema 字段放开发诊断，不进入日常听书流程。

### 14.2 状态显示

区分候选已分析、身份已确认、已生成音频和连续可播秒数。不要用单个“进度 100%”混淆多个阶段。

collect_local_metrics=true 时记录本地指标：首段准备时延、各阶段耗时、连续缓冲、断音次数、重试次数、角色重复候选/冲突数、缓存命中与占用。指标不默认上传外部服务。

retain_debug_payload_days 只用于可清理调试载荷；原文、正式 Allocation、角色/别名依据、合并审计与手动修正不得随之删除。默认不记录书籍全文和原始模型响应，错误展示必须脱敏。

## 15. 默认能力验证与安全边界

本节是实现必要的输入/协议边界，不扩展产品审批流程。

- 开启前验证已选择模型的原生输出协议；不能将 HTTP 200 当作供应商真的执行了 Schema。
- 对音色使用短文本连接测试，核对实际请求 model/voice 大小写和可解码结果。
- 未勾选音色不进入人物选择范围，模型输出越界建议直接拒绝。
- 原始小说只作数据，不能触发网络工具、修改配置或覆盖系统规则。
- 密钥从受保护配置/环境读取，不放系统提示词、任务展示、缓存路径或导出的示例中。
- TLS、重定向、敏感请求头处理沿用项目安全网络层，不禁用证书校验。
- 任何后台动作都遵守用户暂停/停止状态。
- 不以修改超时、无限重试或自动降级普通提示词掩盖接口不兼容。

应用可以严格保证“同一个已确认角色 ID 的绑定不因分块而改变”和“传给 TTS 的原文覆盖完整”。人物身份推断和供应商实际发音质量不能承诺百分之百，必须提供证据、局部修正和明确状态。

## 16. 测试与验收

测试使用可控的模拟文本模型和 TTS，并保留真实供应商联调入口。模拟器要能控制返回顺序、延迟、截断、限流、角色歧义和损坏音频；不能只返回永远成功的固定结果。

### 16.1 配置与协议

| 编号 | 场景 | 通过条件 |
|---|---|---|
| C01 | 解析配套 JSON | 无重复键，Schema 通过，2 个 TTS 供应商、3 个模型配置、5 个音色能全部索引 |
| C02 | X/Y、X/Z、x/y、x/Y | 请求、数据库和缓存键严格区分，原值未被转小写 |
| C03 | 相同 voice_id 位于不同模型 | 路由到正确模型，不通过 voice_id 全局查找 |
| C04 | 旁白不在人物候选池 | 配置有效；系统目录包含两者并集并标明用途 |
| C05 | 并发改为 1 | 保留槽 0，正常推进且无死锁 |
| C06 | extra_body 覆盖 model 或 response_format | 配置报错，不能悄悄覆盖 |
| C07 | 占位配置/功能关闭 | 普通阅读器可用，不请求示例域名或占位密钥 |
| C08 | 原生 Schema 不支持 | 明确报能力不兼容，不改为提示词 JSON |
| C09 | temperature=null、instructions=null | 对应字段被省略，未发送字符串 null |
| C10 | Base URL 含 /v1 | 最终请求保留该路径 |

### 16.2 原文、身份与一致性

| 编号 | 场景 | 通过条件 |
|---|---|---|
| I01 | 李青、阿青、李公子有明确同人证据 | 同一 character_id 与固定音色 |
| I02 | 两个黑衣人/两个人的父亲 | 没有证据不得合并 |
| I03 | 同一句中对白—旁白—对白 | 声音正确切换，两段对白使用同一角色 |
| I04 | 引号跨块、归属说明在后文 | 补足只读上下文，原文不漏读不重复 |
| I05 | 第一人称叙述、书信引用、心理活动 | 按固定规则旁白，不把全部“我”归为人物对白 |
| I06 | 候选块乱序返回 | 有序确认，无竞争造成的双角色或双绑定 |
| I07 | 旧角色快照 | 不盲写；无关版本变化不导致全量重跑，相关歧义局部复核 |
| I08 | 未确定说话人 | 复核后按策略暂时旁白，状态仍为未确定对白，无永久“未知人” |
| I09 | 两个已有角色归并但声线冲突 | 阻塞受影响范围，修正后只重建相关音频，可撤销错误合并 |
| I10 | 从第 20 章首次起听且无前缀状态 | 补前缀人物分析，不合成前 19 章音频，不宣称无需前文即可全书一致 |
| I11 | source units 缺失、重复、乱序、越界 | 校验失败，不能进入 TTS |
| I12 | 原文带表情和重复句子 | 定位准确，不按文本哈希错误去重，Unicode 计数一致 |
| I13 | 模型返回合法 JSON 但角色引用不存在 | 被业务校验拒绝 |

要求并发测试在同一组固定候选结果下与顺序提交获得相同正式绑定；不要求对真实随机模型多次调用得到逐字相同 JSON。

### 16.3 调度、缓存、恢复与播放器

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | TTS 返回顺序为 3、1、4、2 | 播放顺序始终为 1、2、3、4 |
| A02 | 第 2 段缺失而后面均 ready | 连续水位只算到第 1 段，播放器不跳过 |
| A03 | 前方缺口持续失败 | 越缺口窗口、64 个任务、空间预算共同限制后续生成 |
| A04 | 同供应商两个模型同时高负载 | 总并发与 RPM 不超过供应商限制；模型子限额也生效 |
| A05 | 全部后台分析忙，当前需要复核 | 保留席位能推进前沿，没有死锁或永久饥饿 |
| A06 | 1 倍改为 2 倍 | 缓冲秒数相应变化，已有音频不重新合成 |
| A07 | seek 后旧请求返回 | 有效结果可缓存，但不插入新播放队列 |
| A08 | 暂停时仍有在途请求 | 在途可完成，无新增预取，重启后仍暂停 |
| A09 | 多执行者同时认领 | 同一任务只有一个有效 owner/fence |
| A10 | A 租约过期、B 完成、A 迟到 | A 不能覆盖任务、文件索引或当前清单 |
| A11 | HTTP 200 但返回 JSON 错误/坏音频 | 不标 ready，显示可诊断错误 |
| A12 | 下载中崩溃或磁盘满 | 临时文件不被播放，能恢复/重试且无重复入队 |
| A13 | 文件落盘后、事务前崩溃 | 仅留下可处理孤立资产，不产生缺文件的 ready 引用 |
| A14 | 缓存满且当前文件被保护 | 清理其他资产或停止新预取，不删除当前文件 |
| A15 | 修改一个角色音色 | 仅该角色及局部合并单元失效；无关缓存继续命中 |
| A16 | 新增无关人物/修改显示名 | 不使全书音频缓存失效 |
| A17 | 删除/禁用已绑定供应商 | 已缓存内容可播，缺口等待修复，不换声 |
| A18 | 完成一章但下一章尚未就绪 | 等待正确下一章，不重播上一段或误判全书结束 |
| A19 | 多个页面同时打开同一本书 | 不启动多套重复预取循环 |
| A20 | 平台后台挂起及恢复 | 状态可恢复，不承诺挂起期间仍持续执行 |
| A21 | 成功音频被 LRU 淘汰后 seek 回该段 | 原子开启一次本地重建代次，正常播放，不被历史 succeeded 状态卡住 |
| A22 | 播放中改音色造成合成边界变化 | 从原文切换点更新清单，无重读、漏读 |
| A23 | 播放器校验/打开与清理器同时竞争 | 保护或 evicting 原子互斥，无检查后被删的竞态 |
| A24 | 已审核未知对白使用旁白兜底 | 可合成并进入连续缓冲，仍保留未确定对白状态 |
| A25 | 中途起听且前缀首块重试 | 后部候选不占死窗口，前缀顺序推进且不生成前文音频 |

### 16.4 实际验收记录

记录真实使用的供应商、精确模型/音色、并发、水位、首播时延、缓存命中和后台状态。样例书至少包含两个章节、跨章别名、匿名人物、插入旁白和一次身份歧义。

没有用户密钥时完成所有离线和模拟验收，并把真实联调标为“待用户填配置后验证”。禁止捏造测试通过、音频时长或接口兼容性。
